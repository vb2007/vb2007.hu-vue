## Platform

web

## Users
Primary users are the owner (VB2007) and the people they share the site with: friends, acquaintances, and anyone using the tools openly. The site is the owner's own tools hub, built for their own needs and shared publicly. Visitors arrive to get a small job done (shorten a link, paste text or share a file) or to find out what the owner hosts and how to use it.

## Product Purpose
vb2007.hu is a free multi-tool site and the owner's personal website. It has two roles:

1. **Own tools:** general-purpose utilities behind a single account system. URL shortening, a pastebin and file upload and sharing exist today. Other general features are planned.
2. **Directory of hosted services:** a collector for services the owner self-hosts, such as Vaultwarden, a Matrix instance, Kiwix archives, and a public API, plus past full-stack and other projects. These get separate pages on the site. Those pages are display and status information only: what the service offers, how to set it up, how to connect. The services themselves run elsewhere.

Success is a visitor completing a tool task quickly, or understanding what a hosted service offers and how to start using it.

## Positioning
One personal, self-hosted home that holds both working tools and the owner's infrastructure: a single person's stack, openly shared, rather than a commercial SaaS. Its difference is that everything is run by one developer, with the hosted-service pages documenting real services the owner operates.

## Operating Context
- Vue 3 + Vite + TypeScript SPA (vue-router), consuming a separate backend API (`VITE_API_BASE_URL`, default `https://api.vb2007.hu`).
- Accounts exist: register (the account is only created once a 6-digit code mailed to the address is entered) and log in, with a password or with GitHub (the API's OAuth2; the first GitHub login creates the account). Authentication is a `__Host-VB-AUTH` cookie. The URL shortener, creating pastes and uploading files require a logged-in user (the shortener says this "will change in the future"); reading a paste needs no login, and anyone can find pastes without their link (paste ids are MongoDB ObjectIds, and any logged-in user, or any API key with `pastes:read`, can list a user's pastes: vb2007/vb2007.hu-api#592), so nothing private belongs in one.
- Current routes: Home, Shorten (`/shorten`, with the logged-in user's own links under "Your links"), Pastebin (`/pastebin`, plus `/pastebin/:id` for a single paste), Upload (`/upload`), Admin (`/admin` and everything under it, only for the site's superuser: an overview with the site's totals, upload settings and today's mail budget, a link to the API's docs with its admin routes (`/docs/admin` on the API, which only the superuser's session opens), and a key to each section; Users (`/admin/users`), every account's upload usage and quota, searchable by username or e-mail, plus `/admin/users/:id`, one account's page with its logins, suspension, what it owns and its quota, where the admin can rename it, log it out everywhere, see and revoke its API keys, reset its MFA or delete it, and `/admin/users/:id/uploads` to browse and moderate one account's uploads; Pastes (`/admin/pastes`), every paste on the site with its owner, language, date and opening line, searchable by owner or language, to open or delete; Short links (`/admin/short-links`), every account's short links with where they lead and whose they are, searchable by code, target or owner, to check or delete; Uploads (`/admin/uploads`), every account's uploads with whose each is, searchable by file name or owner; System (`/admin/system`), the sign-ups still waiting for their code, and clearing the API's rate limits for an e-mail address or an IP), short link redirects (`/r/:code`, plus `/r/:code/preview` to see where a link leads and who shared it before opening it), Login (with a second step for an account that turned one on, and `/login/mfa`, where the mailed second-step link logs in), Register, Reset password (`/reset-password`: a code or link mailed to the account's address sets a new password), Account (`/account`: the logged-in user's username, e-mail and whether GitHub is linked and as which GitHub login, with a way to link or unlink it, confirmed with the password on an account that has one; an account with a password can change its password, and its e-mail address with that password and a code mailed to the new address, which only takes over once the code is entered (the superuser's is set on the API); an account made with GitHub has no password and can't unlink it until it sets one there, after GitHub confirms it's them; and a way to delete the account, confirmed with the password or, without one, the username after GitHub confirms it's them; and two-step login, where e-mail codes are turned on or off and an authenticator app is set up (by QR code or its key), moved to a new app or turned off, confirmed with the password or GitHub, the first time with ten recovery codes shown once, which can be replaced with a new set; and passkeys, listed with when each was added and last used, added after the password or GitHub confirms it, renamed, or deleted with that confirmation; and links to API keys and ShareX), API keys (`/account/api-keys`: the logged-in user's keys for scripts to use the API as them, listed with their scopes, when they expire and were last used; created with a name, scopes (the admin ones only for the superuser) and a lifetime of 1 to 365 days or none, or rotated, after the password or GitHub confirms it, the token shown once; or deleted. A link, e.g. from an app that needs a key, can open the create form with its name and scopes filled in), ShareX (`/account/sharex`: one key, after the password or GitHub confirms it, creates an API key with the three write scopes ShareX needs and downloads the API's three custom uploaders, for uploads, pastes and short links, with its token filled in, then says which uploader goes in which of ShareX's Destinations), an API error page (`/apierror`, where the API redirects a browser that opens a route it doesn't have) that names the API address as text, and a not-found page for any other path, which names it; both lead home and to the open tools. ## Capabilities and Constraints
- Shipped: URL shortening (create, list, search, copy, delete; logged-in only; links live on the site as `vb2007.hu/r/:code`), pastebin (create, list, view, delete; creating and listing are logged-in only; pastes are syntax-highlighted in the language detected on paste or picked by the user, Markdown renders, and the owner can change a paste's language later), file uploads (upload, list, search, rename, switch public/private, delete, storage meter; logged-in only; files live at `cdn.vb2007.hu/useruploads/<userId>/<uploadId>.<ext>`, public ones open for anyone while they stay public, and anyone can find them and their file names without their link (upload and user ids are MongoDB ObjectIds, mostly creation time plus a counter: vb2007/vb2007.hu-api#527); only the owner and the superuser get a private one's link, which the API signs for an hour and which opens the file for anyone it's shared with until it expires (the site renews the links it shows); 10 GB and 10,000 files per user for now), register, login, logout, password reset by e-mailed code or link, optional two-step login with an e-mailed code or link, an authenticator app's code, a passkey or a saved recovery code that works once, passkeys (added, renamed and deleted on the account page, logging in without a password or second step where the browser supports them), API keys (up to 10 per account, each with its own scopes and lifetime, its token shown only when it's created or rotated), ShareX setup (one key and the three custom uploader files with its token in them), GitHub login and linking or unlinking GitHub on an existing account, setting or changing the account's password, changing its e-mail address, deleting an account with its pastes, short links and uploads, theme switch. The site's one superuser (set on the API) sees on the admin overview how many users, pastes, short links, uploads and waiting sign-ups there are, how much the uploads take, the default quota and largest file, and how much of the day's mail limit the API has used; they can see each account's upload usage and set or reset its quota in the admin area's Users section (`/admin/users`), open an account's page with how it logs in, whether it's suspended and how many pastes, short links and uploads it owns, open, rename, make private or delete any account's uploads from there or from the admin area's Uploads section (`/admin/uploads`), which lists every upload on the site with its owner (or that the account is gone), rename an account, log it out everywhere (its API keys keep working), see its API keys (name, scopes, when each was made, expires and was last used) and revoke them all (its session stays; the superuser's own too), see which MFA methods it has on and reset them for a user who lost their second factor (which also ends their session and deletes their API keys, while their passkeys stay; never the superuser's own), suspend it (which ends its session, deletes its API keys and stops it logging in, with a password or GitHub, while its content stays up) or lift the suspension, and delete it with its pastes, short links and uploads (never the superuser's own), and list, open and delete every paste on the site in the Pastes section (`/admin/pastes`), and in the Short links section (`/admin/short-links`) find any short link by its code, target or owner, open its preview and delete it. Its System section (`/admin/system`) lists the sign-ups still waiting for their code, to remove one so the address can start over, and clears the rate limits counting against an e-mail address or an IP, e.g. when a friend is locked out of logging in. The owner search in the Pastes, Short links and Uploads sections matches part of a username only among the 100 shortest ones containing it (a whole username always finds its owner),, and their counts without a search or filter are estimates, as are the overview's user, paste and short-link totals (exact apart from right after an unclean database shutdown). Nobody else sees the admin area or its link.

## Product Principles
1. **Tools first, immediately usable.** A visitor should reach a working tool in one step and finish its job without friction.
2. **One person's real stack.** Everything shown reflects services and tools the owner actually runs. Never imply scale, a team, or capabilities that do not exist.
3. **Tools and service pages are different kinds of surface.** Tools are interactive. Hosted-service pages inform and point elsewhere. Keep that distinction clear.
4. **Grow without redesign.** New tools and service pages should slot into the same structure as the site expands.
5. **Bilingual from the structure up.** English and Hungarian should both be first-class, not retrofitted.

## Accessibility & Inclusion
Responsive web with working light and dark modes. No formal accessibility standard has been committed. Hungarian and English readers are both audiences.
